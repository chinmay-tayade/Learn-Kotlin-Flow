# Contributing

Thanks for helping improve this learning resource! 🎉

These repositories exist to help Android engineers **learn** — so the most valuable contributions are ones that make a concept *clearer*, not just *more code*.

## How to contribute

1. **Fork** the repository.
2. **Create a branch** for your change: `git checkout -b improve-something`.
3. **Make your change.** Keep it focused on one thing.
4. **Commit** with a clear message describing *why*, not just *what*.
5. **Open a pull request** with a short summary of what changed and why.

## What makes a great contribution

- ✅ **Clarity first** — a simpler explanation, a clearer diagram, a better code comment.
- ✅ **Correctness** — code examples that actually compile and run.
- ✅ **Focused PRs** — one logical change per pull request.

## Code style

- Kotlin code should be **idiomatic** (follow the [Kotlin coding conventions](https://kotlinlang.org/docs/coding-conventions.html)).
- Documentation should be written for **engineers learning the concept**, not people who already know it.
